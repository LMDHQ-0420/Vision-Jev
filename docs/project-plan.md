# 项目完整构思

## 目标

Vision-JEV 的产品形态不是自由生成聊天模型，而是视觉条件下的动态候选判断与动作基座。输入是图片、可见状态、问题和候选集合；输出分为判断模式（Choice/Noul/Score）和策略模式（policy）。首版聚焦单图、2–8 候选，同时训练到 16–32 候选并对 64+ 做压力测试。

## 可验证假设

- H1：去掉完整词表概率特征后，重新训练的隐藏表示头能保留主要能力并减少候选相关计算。
- H2：独立打分加一层残差集合交互能改善需要候选相对比较的任务。
- H2-R：复用视觉网格的区域证据对密集区域候选有增益。
- H3：冻结判断函数、单独训练 PPO actor/value 能提升闭环成功率而不污染判断头参数。

每条假设都必须有同基座、同数据、同视觉预算、同 LoRA rank 的对照。若无收益，按负结果发布，不把已知缓存优化包装成模型创新。

## 阶段与退出条件

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| S0/M0 | 原生处理器契约、schema、合成头测试 | 无答案泄漏，三类输出合法 |
| S1/M1 | 完成 v2.3 来源下载/转换，冻结主干头部预热、50–200 过拟合、12k pilot | 117k 公开数据与 3k API 改写结构、许可和泄漏门禁通过，loss/目标映射正确 |
| S2/M2 | LoRA + 头；隐藏、LM、集合、区域对照 | 同预算结果及失败子集齐全 |
| S3/M3 | 共享前缀推理 | 独立/共享数值等价，缓存隔离，实测有收益 |
| S4/M4 | 120k × 2、独立校准 | 多来源、概率、显存与最坏 shape 审计通过 |
| R0/M5 | MiniGrid 后扩展本地网页环境 | 配对 seed 闭环指标、轨迹与奖励审计完整 |
| M6 | 权重、模型卡、数据卡、教程 | 发布清单全部签署 |

## 止损

LM 特征去除退化则保留混合对照；集合层无稳定增益则默认关闭；区域对齐未通过几何单测不进入训练；R0 无法突破表示限制才考虑 policy-only LoRA 的 R1；任何模块不能仅因已经投入开发而进入最终模型。

## 数据实施顺序（v2）

1. Mind2Web、AndroidControl、RefCOCO、GQA 小样本先跑通适配与泄漏测试。
2. WebLINX、TextVQA、ChartQA 完成原始视觉资产与表格验证；WebLINX 直接采用上游开源内容。
3. 下载并转换 GUI-Odyssey、Visual7W、ScienceQA、NLVR 与 KonIQ-10k，替代全部本地生成配额。
4. 冻结 train/dev/calibration/audit/test 的 root/group 分配，然后生成 pilot 与主 manifest。

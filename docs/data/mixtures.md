# 数据混合与每次搭配记录（v2.2）

每一个训练 run 必须保存 `data_mixture.json`：来源、manifest hash、split、完整问题数、抽样/loss 权重、语言、题型、K 分布、视觉预算、标签来源、过滤器版本、去重与 PII 报告 hash。候选展开行数不能冒充问题数。

## `sft-120k-v2.2`

| 数据块 | Choice | Noul | Score | 合计 |
|---|---:|---:|---:|---:|
| 公开来源 | 76,000 | 14,000 | 0 | 90,000 |
| 程序/环境 | 16,000 | 2,000 | 6,000 | 24,000 |
| 可核验增强 | 4,000 | 2,000 | 0 | 6,000 |
| 合计 | 96,000 | 18,000 | 6,000 | 120,000 |

程序/环境由 8k 动作示范（2k grid + 6k 本地 GUI）、6k 候选集合比较、6k 视觉 Score、4k 已知信息不足组成。增强由 3k 同语言语义改写、2k 程序困难候选、1k 程序重求解反事实组成。新增数据中 27k 由本地程序产生，3k 使用 API 辅助但由程序验证，项目新增人工标注为 0；公开数据集已有的人类标签允许使用。主 manifest 的 `teacher_only=0`。

| 生产路径 | 数量 | 是否调用外部生成 API |
|---|---:|---|
| 公开数据自动下载、转换与抽样 | 90,000 | 否 |
| 本地程序/环境自动生成 | 27,000 | 否 |
| 同语言语义改写并程序验证 | 3,000 | 是 |
| 本项目新增人工标注 | 0 | 否 |

因此完整 120k 中有 117k 不需要生成 API，只有 3k 合格样本需要 API 辅助；API 实际请求次数要在 pilot 后按通过率和重试率记录，不能直接把“3k 合格样本”写成“3k 次请求”。

公开来源的题型子配额也写入配置：GQA 为 10k Choice/8k Noul；实测严格 8/10 一致性后，TextVQA train 只有 1,422 道 Noul，因此 v2.1 将 VQAv2 调为 3.2k Choice/4.8k Noul、TextVQA 调为 4.8k/1.2k，保留 222 道 TextVQA Noul 余量。其余公开来源为 Choice。三者共同使公开块精确达到 76k Choice/14k Noul，构建器按来源与题型双重检查，不以来源总数掩盖题型缺口。

不设置中英文固定配额：公开数据保留原始语言，程序数据保留场景原生语言，增强数据继承父样本语言，不为凑语言比例调用 API 翻译。Choice 的 K 分布为：2–4 占 55%，5–8 占 30%，9–16 占 10%，17–32 占 5%；64/128 只用于压力测试。

任务分布不增加逐条 `task_family` 字段，也不调用 API 分类；按来源用途和 Choice/Noul/Score 汇总。该汇总是来源级近似，不能冒充逐题语义标注。

来源级任务近似分布：GUI/动作 36k、区域指代 18k、关系/组合推理 22k、普通 VQA 8k、OCR 6k、图表 6k、纯文本逻辑 2k、候选集合比较 6k、视觉 Score 6k、信息不足 4k、增强变体 6k。该分布为项目目标导向的非均匀分布；GUI、区域和关系合计 76k，占 63.3%。

## 运行规则

- `pilot-12k-v2.2` 按 v2.2 主配方 10% 分层抽样，只在 50–200 样本过拟合通过后执行。
- 改变任一来源、过滤器、候选器或比例，必须产生新 mixture ID、manifest hash 和迭代记录。
- 头部消融固定数据 hash、顺序、视觉预算、LoRA、优化器和训练步数。
- 来源不足先写缺口报告；只能显式修订配额或降低总量，不能用教师生成静默填补公开来源。
